# Languages (i18n)

Facebook renders its UI in the language of the account. Everything the reader recognises **by words** (dates,
"See more", reaction names, badges, sort labels, count suffixes) is therefore language data. It lives in
`PACKS` at the top of `scripts/fb-reader.js`, not in the logic.

## Status

| Pack | State |
|---|---|
| `hu` | verified against the real Facebook UI (`verified: true`) |
| `en` | complete for the reading core, not yet verified on a real English UI |
| anything else | not available — add a pack (below) |

`__fbReader.lang()` → `{page, code, supported, verified, packs}`. `selfTest()` warns when the page language has
no pack or only an unverified one. The reader always works with the **union** of all packs; the page language
is only reported, never used to switch behaviour.

## What a pack contains

```js
{
  id: 'de', name: 'Deutsch', verified: false,
  months: { januar: 0, februar: 1, 'märz': 2, /* … */ okt: 9 },      // name or abbreviation → 0-based month
  rel: {
    long:  { sec: [], min: ['minuten','minute'], hour: ['stunden','stunde'], day: [...], week: [...], month: [...], year: [...] },  // "ago" words
    short: { min: ['min'], hour: ['std'], day: ['t'] },                                                   // "3h", "5 p", "2d"
    one: ['vor einer', 'vor einem'],   // "an hour ago" — only combined with long units
    agoPre: ['vor'],                   // optional prefix word ("vor 3 Stunden", "hace 3 horas")
    ago: [],                           // optional suffix word ("3 hours ago")
    now: ['gerade eben'], yesterday: ['gestern'], am: [], pm: [],
  },
  count: { k: ['tsd'], m: ['mio'] },   // "1,2 Tsd." → 1200
  w: {                                 // literal lowercase phrases
    seeMore, seeLess, translate, viewPost, sponsored, verified, person, noise, keep
  },
  r: {                                 // regex SOURCE fragments, case-insensitive, no ^ $ (anchors are added)
    publish,        // REQUIRED: publish / send / like / join / delete … words — the click guard refuses to press these
    reaction, reactionsWord, commentsWord, sharesWord, commentLabel, moreComments, uiLine,
    pinned, authorBadge, badgeLine, sortAll, sortNewest, sortRelevant, sortOther,
    postBy, replyTo, reactionAttr, verifiedAttr, skipDateLabel
  },
  commentLabels: [ { re: '^kommentar von (.+?) (.+)$', a: 1, to: 2, when: 3 } ],  // aria-label of a comment
}
```

`registerLang(pack)` validates the pack, rebuilds every derived regular expression and returns the ids of all
known packs. A pack without `r.publish` is refused: **the publish words are a safety feature**, not a
convenience. A refused pack leaves nothing behind.

## Adding a language — procedure

1. Open Facebook in that language (Settings → Language and region) and a page with posts and comments.
2. Run `__fbReader.langProbe()`. It lists the date strings it could not parse, posts without counters and the
   button labels it does not know.
3. Copy the `en` entry (it is the smallest complete one), translate the words, and fix what `langProbe()`
   reported. Keep the **union** in mind: a short word that is also a common word in another language (an
   article like "a", the unit "m") can misfire — that is why `rel.one` is only combined with long units.
4. Try it without touching the source: `__fbReader.registerLang({…})`, then `selfTest()`, `map()`,
   `thread('#…')`. Dates, counts, the author badge, pinned comments, "sponsored" and the sort menu are the
   usual weak spots.
5. When it reads a real page correctly, add the entry to `PACKS`, set `verified: true` only if you tested it on
   the real UI, add a synthetic fixture in `tests/pages/` and a block in `tests/run_tests.py` (see the
   `languages` section), run `scripts/build.py` and the suite.

The **write guard hook** (`hooks/fb-write-guard.mjs`) looks at the `action_summary`
that Claude writes for each click. It recognises English and Hungarian verbs; a summary in any other language is
never treated as a read — it is asked about. That is the safe default. Keep summaries in English.

## What is pack-driven today (phase 1)

Post reading core: dates (absolute and relative), counts and suffixes, reactions, comment labels (author,
addressee, age), pinned / author / top-fan badges, sponsored, verified, "See more" / "See less" / translation,
"more comments", sort menu, UI-noise lines, the click guard's publish words, snapshot anonymiser vocabulary,
notification time lines.

## Still inline, Hungarian + English (phase 2)

These parts work in Hungarian and English only, by regular expressions written next to the code. Moving them
into the packs follows the same recipe (a new `r` / `w` key and a derived constant):

- **Notifications:** `NOTIF_KINDS`, `NOTIF_TEXT_KINDS`, the "mark as read" / "unread" labels, `inbox()` header labels.
- **Messages:** unread marker, "active now", compose-box name labels, group-chat marker, thread-header words.
- **Marketplace:** `MK_BADGE`, `MK_SPONS`, price words (`ingyenes` / `free`), currency list, filter button labels
  (`Rendezés` / `Sort`, `Helyszín` / `Location`), "no results".
- **Tracking:** `TRK_SOLD`, `TRK_STATS`, `TRK_INQ` (sold / pending words, counters, inquiry words).
- **Selling (write module):** form control labels (`SELL_BTN`, `SELL_COMBO`, `SELL_SWITCH`), `MK_CONTROLS`.
- **Write module:** send / like / emoji button labels (`SEND_EXACT`, `SEND_LIKE`), compose-box and reply-box labels,
  `notifMore`, `msgSearch`, `msgRequests` locators.
- `ACTION_RE` (profile action buttons).

## Output language (phase 2)

The reader's *output* — status lines, warnings, the permission prompts of the hook, the approval texts — is
Hungarian today. Claude understands it and answers in the user's language, but the hook prompts are shown to
the user directly. A message catalogue (`hooks/messages.mjs` + a `messages` table for the reader, language from
the page / a config file) is the next step; until then a non-Hungarian user reads Hungarian permission prompts.
